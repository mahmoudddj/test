# Methodological risks and how the software handles them

These are technical-lead positions. Several protocol elements must not be propagated blindly into the analysis.

| # | Risk | Consequence if ignored | What the software does | What the study team must decide |
|---|---|---|---|---|
| 1 | **Repeated images per patient are correlated** | CIs far too narrow; inflated significance | all CIs by patient-cluster bootstrap; GEE/mixed models; plain logistic regression refuses repeated rows; episode-level metrics reported alongside image-level ones | primary unit of analysis (episode/event) in the SAP |
| 2 | **Patient-level leakage** (random image splits) | grossly optimistic AUROC | splits at patient level only, asserted on every build and before training | site hold-out for external validation? |
| 3 | **Temporal / label leakage** (labs reported after prediction, post-diagnosis images, antibiotics given because infection was suspected) | model "detects" infection from its consequences | availability time per variable; post-recognition samples excluded; antibiotic feature only if known at *t*; leakage assertion | whether antibiotics/assessments may be predictors at all (they encode clinician suspicion) |
| 4 | **~100 patients, maybe 20–35 events** | deep networks overfit; unstable estimates | interpretable baselines first (clinical + thermal ΔT logistic regression); transfer learning with frozen/finetuned small CNNs; ViT config warns; event counts in every report | power/precision calculation for the primary endpoint; minimum events before deep models are evaluated |
| 5 | **Class imbalance** (6–10 % positive samples) | accuracy meaningless; thresholds unstable | AUPRC, PPV, alert PPV, false alerts per catheter-day; pos-weight / weighted sampler; thresholds from validation | operating-point rule (e.g. sensitivity ≥ 0.85) fixed a priori |
| 6 | **Project KPIs as analysis targets** (≥ 6 h earlier, precision/recall ≥ 85 %) | KPI-driven threshold tuning on test data | KPIs reported, never used for selection; test set locked + ledger | — |
| 7 | **Reference standard** (ESI/tunnel/CRBSI definitions, clinician-labelled) | label noise, incorporation bias | blinded independent double reading, adjudication by a non-reader, versioned labels, kappa with CIs; model never creates labels | written criteria (IDSA/CDC version), adjudication charter, blinding profile for reference labels |
| 8 | **Comparator definition** ("conventional detection time") | lead time ill-defined | `clinical_recognition_time` mandatory for events, distinct from adjudicated onset | operational definition (first documented suspicion? culture? treatment start?) |
| 9 | **Observation opportunity** (imaging every 12 h limits possible lead time) | lead time capped by schedule; missing images bias detection | reports events without a ≥ 6 h detection opportunity; missing timepoints on the DQ dashboard | imaging frequency per setting; handling of missed acquisitions |
| 10 | **Acquisition variability** (camera, distance, ambient, emissivity, angle, skin type) | site/camera effects masquerade as signal | mandatory metadata + QC; cross-site comparison; ambient-corrected and within-episode baseline features; site-stratified metrics; skin phototype recorded for fairness analyses | standardised acquisition SOP + training; one camera model if possible |
| 11 | **Non-radiometric images** (palette JPEG) | colour-map pixels ≠ temperature; models learn rendering artefacts | flagged non-radiometric (WARNING) and excluded by default from ML datasets | require radiometric export from the camera workflow |
| 12 | **Competing events** (removal for other reasons, death, discharge) | KM overestimates incidence | censoring reason recorded; flagged in docs | cumulative-incidence (Aalen–Johansen) sensitivity analysis in the SAP |
| 13 | **Missing data** | bias; hidden missingness | explicit missing codes, indicators, missingness reports by split/site; outcomes never imputed | imputation strategy for the primary model |
| 14 | **Interpretability over-claiming** | heat maps read as proof | caveats stored with every Grad-CAM/attribution; "not causal" wording in UI | — |
| 15 | **Multiple models/subgroups** | false discoveries | primary/secondary/exploratory labels; analysis registry records the configuration used | pre-registration of the primary model and analysis |
| 16 | **Synthetic data** | mistaken for real results | everything synthetic is named/flagged SYNTHETIC; the positive-control test only checks the pipeline | never report synthetic metrics |
